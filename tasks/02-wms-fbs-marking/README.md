# 02. Склад: сборка FBS, сканы и инвентаризация

Учебные данные. Исходные файлы в `data/` скрипт не изменяет.

## Запуск

Из папки `tasks/02-wms-fbs-marking`:

```text
php warehouse.php
```

Нужен PHP 8.1+. Результат печатается в консоль и записывается в `report/`:

- `report.txt` — общий отчёт;
- `pick-list.csv` — маршрут по ячейкам;
- `pick-shortages.csv` — чего не хватило;
- `scan-issues.csv` — ошибки сканов;
- `inventory.csv` — сравнение учёта и пересчёта, включая совпавшие ячейки.

## Решения

Лист подбора строится по сроку `ship_by`: более раннее задание забирает остаток первым. При равном сроке порядок по номеру задания. Нулевой остаток в ячейке не используется. Если артикул лежит в нескольких ячейках, сначала берётся ячейка с меньшим кодом. Маршрут для кладовщика отсортирован по ячейке. Задание, в котором не хватило хотя бы одной позиции, в отгрузку не ставится. Доступная часть такого задания в маршруте есть, но помечена «не отгружать».

Скан маркированного товара без кода или с чужим кодом не считается собранной единицей. Повтор одного КИЗ тоже не считается второй штукой: засчитывается только первое вхождение. Одинаковый штрихкод без маркировки может встречаться несколько раз: это разные штуки.

Инвентаризация сравнивает количество внутри ячейки. Ячейка, которой нет в пересчёте, не списывается как недостача. Если по ячейкам артикул разъехался, а сумма по складу сошлась, это указано отдельно как возможное перемещение.

## Как не доводить ошибки до отгрузки

Не закрывать задание, пока число принятых сканов не равно заданию, а у маркированного товара нет верного КИЗ. Повтор кода маркировки блокировать сразу, в том числе если первое сканирование было в другом задании. В лист подбора не отдавать позицию, если после более срочных заданий остатка уже нет. Пересчёт проводить по всем ячейкам; неизвестный штрихкод и товар в чужой ячейке оставлять до проверки, а не отгружать. Перемещение между ячейками записывать в учёт до следующей сборки.
